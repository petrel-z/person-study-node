## 一、本阶段要解决的核心问题

这一阶段不要急着学 TCP 三次握手，也不要急着背一堆协议名。

先解决 6 个基础问题：

1. 为什么网络要分层？
2. TCP/IP 四层模型分别是哪四层？
3. 每一层到底解决什么问题？
4. 数据从应用发出去时，是如何一层层封装的？
5. 数据到达对方机器后，是如何一层层解封装的？
6. 浏览器访问网站时，HTTP、TCP、IP、网卡分别在干什么？

## 四、7 天详细计划

### Day 1：先建立直觉，为什么网络要分层？

学习目标：

- 明白网络分层不是为了考试，而是为了降低复杂度。
- 初步理解“每层只负责自己的事”。

阅读任务：

- 阅读小林《TCP/IP 网络模型有哪几层？》开头到“应用层”之前。

要理解的内容：

- 不同设备之间通信为什么需要统一协议。
- 网络为什么要拆成多层。
- 每一层之间通过接口协作。

类比理解：

- 应用层像寄件人，只关心我要寄什么。
- 传输层像快递公司前台，负责把货物分批、编号、交付。
- 网络层像路线规划，负责往哪个方向走。
- 网络接口层像快递车、道路和具体小区门牌，负责在局部链路上传输。

当天输出：

- 写一段 100 字左右的解释：为什么网络要分层？
- 画一张“寄快递类比网络分层”的图。

自测题：

1. 如果没有分层，网络通信会变复杂在哪里？
2. 分层后，每一层为什么可以相对独立变化？
3. 应用程序需要关心网线怎么传输电信号吗？为什么？

通过标准：

- [ ] 我能说出“分层是为了降低复杂度和隔离变化”。
- [ ] 我能用寄快递类比解释网络分层。
- [ ] 我能接受“上层使用下层服务，下层不关心上层细节”这个思想。

- 理解质量：/5
- 表达质量：/5
- 思考质量：/5

### Day 2：应用层，离用户最近的一层

学习目标：

- 知道应用层负责为用户提供具体网络功能。
- 知道 HTTP、DNS、FTP、SMTP 等属于应用层协议。

阅读任务：

- 阅读小林《TCP/IP 网络模型有哪几层？》中的“应用层”部分。

要理解的内容：

- 应用层在操作系统用户态。
- 应用层负责产生应用数据。
- 应用层不负责把数据真正送到对方机器。

关键句：

- 应用层关心“我要做什么网络应用”。
- 应用层不关心“数据具体怎么穿过网络”。

例子：

- 浏览器访问网页：HTTP / HTTPS
- 域名解析：DNS
- 发邮件：SMTP
- 文件传输：FTP

当天输出：

- 写出 4 个应用层协议，并说明它们各自解决什么问题。
- 用自己的话解释：为什么 HTTP 属于应用层？

自测题：

1. 浏览器是应用层的软件吗？
2. HTTP 协议负责保证数据一定送达吗？
3. DNS 解决的是什么问题？

通过标准：

- [ ] 我能说出应用层的职责。
- [ ] 我能举出至少 3 个应用层协议。
- [ ] 我能说明应用层为什么不负责可靠传输。

### Day 3：传输层，负责应用到应用的通信

学习目标：

- 理解传输层不是“机器到机器”，而是“应用进程到应用进程”。
- 初步认识 TCP、UDP、端口、分段。

阅读任务：

- 阅读小林《TCP/IP 网络模型有哪几层？》中的“传输层”部分。

要理解的内容：

- 传输层给应用层提供网络支持。
- TCP 更可靠，UDP 更简单、更快。
- 端口号用于区分同一台机器上的不同应用。
- 数据太大时，传输层会进行分段。

关键概念：

- TCP
- UDP
- 端口
- TCP 段
- MSS

### Day 4：网络层，负责把包送到目标设备附近

学习目标：

- 理解网络层负责主机到主机的路径选择。
- 初步认识 IP、IP 包、路由、MTU。

阅读任务：

- 阅读小林《TCP/IP 网络模型有哪几层？》中的“网络层”部分。

要理解的内容：

- 传输层不负责规划复杂网络路径。
- 网络层负责在复杂网络中找到目标设备。
- IP 协议会给传输层数据加上 IP 头部。
- IP 报文如果超过 MTU，可能会分片。

关键概念：

- IP
- IP 地址
- IP 包
- 路由
- MTU

### Day 5：网络接口层，真正把数据发到局部网络

学习目标：

- 理解网络接口层负责链路级别传输。
- 初步认识 MAC 地址、以太网、Wi-Fi、ARP、帧。

阅读任务：

- 阅读小林《TCP/IP 网络模型有哪几层？》中的“网络接口层”部分。

要理解的内容：

- IP 地址用于网络层寻址。
- MAC 地址用于局域网内的链路层寻址。
- 网络接口层会加上 MAC 头部，封装成数据帧。
- ARP 可以根据 IP 地址获取对应 MAC 地址。

关键概念：

- MAC 地址
- 以太网
- Wi-Fi
- ARP
- 数据帧

### Day 6：封装与解封装，把四层串起来

学习目标：

- 把应用层、传输层、网络层、网络接口层连成完整流程。
- 理解数据发出时不断加头部，接收时不断拆头部。

阅读任务：

- 回看小林《TCP/IP 网络模型有哪几层？》中的总结和封装图。

要理解的内容：

发送方向：

```text
应用数据
-> 加 TCP/UDP 头部，变成传输层报文
-> 加 IP 头部，变成 IP 包
-> 加 MAC 头部，变成数据帧
-> 通过网卡发出去
```

接收方向：

```text
数据帧
-> 去掉 MAC 头部
-> 去掉 IP 头部
-> 去掉 TCP/UDP 头部
-> 交给应用程序
```

## 五、本阶段重难点

### 最重要的 4 个点

1. **分层思想**
   网络不是一坨东西，而是按职责拆开。每层只处理自己该处理的问题。

2. **传输层和网络层的区别**
   传输层更关心“哪个应用到哪个应用”，网络层更关心“哪台主机到哪台主机”。

3. **IP 地址和 MAC 地址的区别**
   IP 地址用于跨网络定位目标方向，MAC 地址用于局域网内链路传输。

4. **封装和解封装**
   发送方一层层加头部，接收方一层层拆头部。

### 最容易混淆的 5 个点

| 容易混淆 | 正确理解 |
| --- | --- |
| HTTP 负责传输可靠性 | HTTP 只是应用层协议，可靠性通常由 TCP 提供 |
| IP 地址能定位具体应用 | IP 地址定位主机，端口号定位主机上的应用 |
| 传输层负责找路 | 找路主要是网络层的事情 |
| 有 IP 就不需要 MAC | IP 和 MAC 工作范围不同，局域网传输仍需要 MAC |
| 背出四层就算懂 | 能把真实访问网站过程放进四层模型，才算开始懂 |
