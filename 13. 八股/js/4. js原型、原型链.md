# 基础
## 1. 原型、原型对象、原型链的核心定义
**原型（prototype）** ：这个属性就是原型，只有函数才有这个属性，该属性指向一个普通对象，这个对象就是该函数的原型对象
**原型对象** ：他就是原型指向的对象（显示原型），包含所有实例共享的所有属性和方法，默认有一个constructor属性，指向构造函数
**对象原型**：所有对象都有一个属性，叫_proto_（隐式原型），它指向该对象的原型对象。
**原型链** ：在访问一个对象的属性或方法时，发现该对象中不含有某个属性或方法，那么会通过_proto_属性来查找该对象的原型对象（prototype），查看原型中是否有该属性和方法，如果有则使用原型对象中的属性和方法，如果没有，则继续根据原型对象的_proto_属性查找上一级原型对象，知道倒找Object.prototype，结束整条链的查找（原型链的工作原理）

## 2. 构造函数、实例对象、原型对象三者的关系
构造函数可以通过new 来创建实例对象
创建过程中，实例对象会有一个_proto_属性，会指向该构造函数的prototype，也就是该构造函数的原型对象


## 3. 为什么要有原型这个机制？（核心作用和设计思想）

是为了解决每次通过构造函数和new创建一个实例对象时，都需要重复定义该实例的属性和方法，及时实例之间有重复的属性和方法，从而带来内存浪费的问题。

因此原型的设计初衷就是为了让实例共享构造函数的属性和方法
可以通过修改实例对象的proto，或者修改构造函数的prototype指向来实现继承


## 4. 原型链的顶端为什么是null
	Object.protorype._proto__   =  null
结束原型链，防止在查找的的时候进入无限循环

# 进阶

## 1.  new 操作符原理
就是通过new 创建了一个对象，
这个对象this变成构造函数的this
让该对象的_proto_指向构造函数的原型
从而实现：对象可以共享构造函数原型上的方法和属性


## 2. 如何判断一个属性是「对象自身的属性」还是「原型链上的属性」？

通过Object原型上的hasOwnProperty属性，判断一个属性时在对象上还是在它的原型链上
当hasOwnProperty返回true，说明该属性存在于该实例对象上；若为false，则说明该属性存在于该实例的原型链上

## 3. `in`操作符和`hasOwnProperty`的区别是什么？

in 是为了检查属性是否在该对象或者该对象的原型链上
hasOwnProperty则是判断属性在该对象上还是对象的原型链上
当 prop in obj && !obj.hasOwnProperty(prop) 表示该属性在原型链上
prop in obj && obj.hasOwnProperty(prop) 表示该属性在该对象上

## 4. 实现原型继承的方式有哪些
### 1. 原型链继承
核心就是两个构造函数，一个父，一个子，子要继承父
需要将子的prototype指向父的实例
并将子的prototype的constructor指向子构造函数
```js
function Parent() { name: '张三'};
funciton Child() {};
Child.prototype = new Parent();
Child.prototype.constructor = Child;
```

优点：子实例能够继承父构造函数的方法和属性
缺点：
1. 子实例会共享到构造函数的引用类型属性，当一处修改时，所有地方的该属性都会被修改
2. 子实例不被创建时，不能向父构造函数传参


### 2. 构造函数继承

```js
function Parent(name) {
	this.name = name;
	this.arr = [1, 2];
}
function Child(name) {
	Parent.apply(this, name); // apply 也行
}
```
优点：解决了1的两个缺点
缺点：

### 3. 组合式继承
结合了1和2
```js
function Parent(name) {
	this.name = name;
	this.arr = [1, 2];
}
function Child(name, age) {
	Parent.apply(this, name); // apply 也行
	this.age = age;
}
Child.prototype = new Parent();
Child.prototype.constructor = Child;
```
优点：
1. 能传参
2. 能继承父的原型上的方法和属性

缺点：
1. 调用了2次Parent（）
2. 在Child的prototype上添加了父类的属性和方法

### 4. 寄生组合式继承

```js
function Parent(name) {
	this.name = name;
	this.arr = [1, 2];
}
function Child(name, age) {
	Parent.apply(this, name); // apply 也行
	this.age = age;
}
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;

```

Object.create(proto)：创建一个空对象，将该空对象的prototype就是proto

优点：
1. 原型属性不会被共享
2. 可以继承父类的原型链上的属性和方法
3. 只调用了一次Parent()，不会在Child的prototype上添加Parent的属性和方法

缺点：
1. Child.prototype的原始属性和方法会丢失



# 混淆

## 1. 原型链和作用域链的区别
原型链：
1. 解决的是对象的属性和方法的查找问题
2. 查找方向：从下到上

作用域链：
1. 解决的是变量和函数的查找问题
2. 查找方向：从里到外
3. 与函数执行有关，函数执行时，会创建作用域链，执行完毕后销毁


## 2. 为什么基本数据类型能调用方法
toString toFixed slice

为什么基本数据类型能调用这些方法
'123'.toString()
因为当js在执行这个代码时的瞬间，会创建该基本数据类型对应的包装对象（内置的构造函数实例），包装对象的_proto_指向了对应构造函数的原型，能调用原型上的方法，执行完毕后，该包装对象会被js销毁。
