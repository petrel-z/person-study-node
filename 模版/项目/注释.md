
 优化一下注释,删除多余的注释.必须有：文件头部注释、复杂业务逻辑注释、公共函数文档注释、特殊标记注释、兼容 /hack
  注释、多分支逻辑、常量 / 枚举、关键变量注释；
  不需要写多余的注释，如：复述代码、无意义、过于细节、过时的注释。




## 核心原则 (Core Principles)
1. **优先自解释**: 优化命名和结构，使代码本身清晰易懂。注释应作为代码无法表达意图时的补充。
2. **解释“为什么”而非“做什么”**: 不要复述代码逻辑，重点说明设计意图、业务背景或技术约束。

## 注释规范 (The "Do's")
- **Intent (意图)**: 解释为什么选择某种特定算法、超时时间或处理方式。
- **Docstrings**: 为函数/类提供标准的文档字符串（包含 Args, Returns, Raises）。
- **Complex Logic**: 简述晦涩的正则、数学公式或复杂的位运算逻辑。
- **Warnings/Gotchas**: 标记潜在的坑点、副作用或特殊的业务限制。
- **TODO**: 记录未完成的功能或已知的待优化点。

## 禁止项 (The "Don'ts")
- **Obvious Noise**: 严禁复述代码字面意思（如：`i = i + 1 # i 加 1`）。
- **Git Metadata**: 严禁记录作者、日期或修改记录（这些由 Git 处理）。
- **Zombie Code**: 严禁保留被注释掉的大段废弃代码。
- **Outdated Info**: 严禁保留与当前代码逻辑不符的旧注释。
- **Emotional Venting**: 严禁包含个人情绪或吐槽。

## 输出格式
- 使用 Python 风格的 PEP 257 (Docstrings) 或 Google 风格。
- 行内注释保持简洁，与代码之间保留至少两个空格。
