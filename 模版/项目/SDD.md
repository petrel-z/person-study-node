# 三、SDD最终完整流程
1. **需求文档** → 做什么
2. **设计文档** → 怎么做
3. **评审** → 确认没错
4. **任务拆解** → 拆分步骤
5. **项目初始化 + 架构搭建** → 搭骨架
6. **开发编码** → 正式写代码
7. **自测 + 测试**
8. **发布**


## 1. 评审（最关键）
- 需求评审：确认功能没错
- 技术评审：确认架构、技术栈、模块没问题

**目的：统一理解，避免后期返工。**

## 2. 任务拆解（开发的真正起点）
把大项目拆成小任务，例如：
- 初始化项目
- 命令解析模块
- 交互模块
- 配置生成模块
- 文件读写模块
- 测试

**不拆解就开发，一定会写乱。**

## 3. 技术准备 & 脚手架搭建
- 新建项目
- 引入依赖（clap / serde_yaml / dialoguer）
- 搭建目录结构（DDD 分层）
- 写基础工具类

## 4. 定义核心数据结构（非常重要）
- 结构体
- 枚举
- 配置模型
- 接口/方法定义

**这一步做完，代码就水到渠成。**
