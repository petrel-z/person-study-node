# 项目梳理
### 登录：
表单验证成功：

- 路由在跳转之前，对跳转有限制：

	2. 若用户已经登录

	3. 用户未登录
		1. 禁止用户跳转除了登录页面的其他页面——清除cookie里的信息，并重定向到登录页
	4. 其他情况才能正常路由跳转

### 年度报告
- 用户点击生成数据按钮
	- 调generate接口，通知后端开始生成数据
	- 订阅sse事件
	- 通过sse返回进度，生成完毕后，通过sse返回二维码图片
		- 正常接受
			- 处理数据：展示用户进度
			- 收到二维码：直接展示，并且用户不用重新生成
		- 异常情况：sse中断
			- 用户退出登录、关闭网页：登录后不能使用sse接收进度数据，只能通过progress接口获取
				- 将sse状态存储在本地，持久化存储
			- sse传输超时：用户可重新通过sse获取进度数据
				- 将sse状态存储在会话层


生成数据时：
1. sse通讯过程中：
	1. 系统原因：后端未生成，返回给前端生成失败，此时用户可重新生成
	2. 用户操作：用户不可重新生成，此外只能通过接口
		1. 退出登录、关闭整个网页：虽然sse会断开，但后端不会停止数据生成
		2. 关闭弹窗（相当于关闭页面）：只是关闭了通道，sse还可以接收数据，只要接收到，就会通过mmit分发，如果用户重新打开了页面，后端还在返数据，那么就能继续通过mmit获取到数据


业务逻辑：
1. 用户点击按钮，触发sse，通讯开始，前端通过sse接收后端返回的数据
2. sse未断开：通讯过程中，前端根据status字段，判断成功还是失败
	1. 后端生成失败，前端展示用户生成失败，请重新生成
	2. 后端生成成功，前端直接展示二维码，并保存在会话层
3. sse断开（关闭弹窗、关闭网页、退出登录）：
	1. 根据获取进度接口获取进度和二维码
		1. 获取成功，展示给用户
		2. 获取失败
			1. 后端生成失败，提示用户失败，并重新生成

**主要实现步骤：**

1. **准备可分享的元素**：
    - 在H5中设计好要生成图片的内容，通常是`<div>`包裹的背景、文字、用户头像、昵称、二维码等。
    - 将这些内容通过CSS定位（`position: absolute`）放在一个父容器里，避免生成时元素错位。
    - 为方便生成，可以使用`z-index`将不希望在最终图片上出现的元素（如操作按钮）临时隐藏。
2. **使用HTML2Canvas**：
    - 引入`html2canvas`库。
    - 在点击事件中，调用`html2canvas(document.getElementById('your-container-id'))`，获取到Canvas对象。
    - **关键：图片处理**。如果模板中有图片，要确保图片加载完成，否则可能为空白。可使用`load`事件监听图片加载，或用`Promise`处理所有图片加载完毕再生成。
3. **生成图片并展示**：
    - `canvas.toDataURL("image/png")` 将Canvas转成Base64图片字符串。
    - 将这个Base64字符串显示到页面上（例如用`<img>`标签），用户长按即可保存到手机相册。
    - **下载功能**（PC端/移动端）：模拟点击一个`<a>`标签，设置`href`为`toDataURL`的图片，并添加`download="filename.png"`属性。
4. **优化微信分享（可选）**：
    - 引入**微信JS-SDK** 掘金社区https://juejin.cn/post/7121556328434434085，进行微信JS-SDK配置https://juejin.cn/post/7121556328434434085。
    - 利用JS-SDK的`updateAppMessageShareData` (分享给朋友) 和 `updateTimelineShareData` (分享到朋友圈) API，传入自定义的标题、描述、图片（通常是生成图片后上传到服务器，返回URL）来优化分享效果。 

**常用库 & 工具**：

- **HTML2Canvas**：将DOM转为Canvas图片。
- **qrcode.min.js**：生成二维码。
- **微信JS-SDK**：实现微信内的分享功能。 

总结流程：设计模板 -> 引入库 -> 点击事件捕获 -> HTML2Canvas -> toDataURL -> 展示/下载。
