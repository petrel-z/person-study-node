### 问题一：
推送到github上，出现了pnpm版本不一致问题
由于packjson文件中，没有规定pnpm的版本，所以会下载最新的pnpm版本，但是由于6小时之前，pnpm更新到了11.0.8，这个版本必须是node 22，但是我用的是node 20，所以就导致ci过不去。

pnpm v11 在这几天发布了。由于你的配置没锁定版本，它自动升级到了 v11，而 v11 强制要求 Node.js 22。你的环境是 Node 20，导致 node:sqlite 模块找不到而崩溃。


### 问题二
[root@VM-0-13-opencloudos blog]# git status && git branch
On branch main
Untracked files:
(use "git add <file>..." to include in what will be committed)
blog@0.1.0
next
package-lock.json
nothing added to commit but untracked files present (use "git add" to track)
* main

然后我运行了：
1. 将修复推送到远程 dev
git push origin dev
2. 切换到 main 分支
git checkout main
3. 拉取远程最新的 main (防止落后)
git pull origin main
4. 合并 dev 的修复
git merge dev
5. 推送到远程 main (这会触发 GitHub Actions 部署)
git push origin main
使得最后运行git status && git branch 就没问题了


### 经验教训（避坑指南）
- 锁定工具版本： 永远在 package.json 里锁定 packageManager 。
- 不要在服务器手动改代码： 服务器上的 git status 应该是干净的。出现 package-lock.json 说明有人在服务器跑了 npm install ，这会破坏 pnpm 的依赖链。
- 善用强制刷新： 每次部署完，先 Ctrl + F5 排除浏览器缓存干扰。
- 看日志要看关键行： 看到 Successfully connected to production database 才代表你的新代码真的“活”了。
