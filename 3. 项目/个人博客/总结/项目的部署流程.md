# Next.js 个人博客服务器部署全流程指南
## 一、部署环境与前置准备
### 1. 环境说明
- 服务器：腾讯云 OpenCloudOS 系统（root 用户）
- 项目：Next.js + Prisma 个人博客
- 工具：PM2（进程守护）、Nginx（反向代理）、Git（代码拉取）
- 域名：`petrel-z.asia`（阿里云注册）

### 2. 前置准备
1.  服务器已安装 Node.js、npm、PM2、Nginx、Git
2.  域名已完成实名认证，准备好服务器公网 IP（示例：`129.211.1.107`）
3.  项目代码已推送到远程仓库（Gitee/GitHub）

## 二、完整部署步骤
### 步骤 1：拉取项目代码（解决大体积上传问题）
**核心优化**：避免本地直接上传 `node_modules`/`.git` 等冗余文件夹，通过 Git 拉取源码，体积小、速度快。
```bash
ssh root@129.211.1.107
# 1. 进入服务器根目录
cd /root
# 2. 克隆项目（推荐 Gitee 国内镜像，速度更快）
git clone --depth=1 https://gitee.com/zhao-hai-yan/blog.git
# 3. 进入项目目录
cd blog
```

### 步骤 2：安装依赖与项目构建
```bash
# 1. 安装项目依赖（服务器生成 Linux 兼容的 node_modules）
npm install
# 2. 构建 Next.js 生产版本
npm run build
# 3. Prisma 数据库初始化（根据项目脚本执行）
npm run db:generate
npm run db:migrate
```

### 步骤 3：PM2 进程守护（24 小时后台运行）
```bash
# 1. 启动项目，命名为 blog
pm2 start "npm run start" --name "blog"
# 2. 设置服务器开机自启
pm2 startup
# 3. 保存当前进程列表，确保重启后自动恢复
pm2 save
# 4. 验证进程状态（status 显示 online 即为正常）
pm2 status
```

### 步骤 4：Nginx 反向代理配置（域名/IP 访问）
#### 4.1 编写 Nginx 配置文件
```bash
# 一键写入配置（无需手动编辑，避免语法错误）
cat > /etc/nginx/conf.d/blog.conf << 'EOF'
server {
    listen 80;
    server_name petrel-z.asia www.petrel-z.asia _;

    # 优化超时时间，避免 502 错误
    proxy_connect_timeout 60s;
    proxy_send_timeout 60s;
    proxy_read_timeout 60s;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Next.js 静态资源缓存优化
    location /_next/static/ {
        alias /root/blog/.next/static/;
        expires 365d;
        access_log off;
    }
}
EOF


cat > /etc/nginx/conf.d/blog.conf << 'EOF'
server {
    listen 80;
    server_name 129.211.1.107;

    location / {
        proxy_pass         http://127.0.0.1:3000;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}
EOF
server {
    listen 80;
    server_name petrel-z.asia www.petrel-z.asia;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

#### 4.2 验证配置并重启 Nginx
```bash
# 1. 检查配置语法是否正确
nginx -t
# 2. 重启 Nginx 生效配置
systemctl restart nginx
# 3. 验证 Nginx 运行状态
systemctl status nginx
```

### 步骤 5：域名解析配置（阿里云控制台）
1.  进入阿里云域名控制台 → 找到 `petrel-z.asia` → 点击「域名解析」
2.  添加两条 **A 记录**：
    | 记录类型 | 主机记录 | 记录值（服务器 IP） | TTL |
    |----------|----------|----------------------|-----|
    | A        | @        | 129.211.1.107        | 60秒（加速生效） |
    | A        | www      | 129.211.1.107        | 60秒（加速生效） |
3.  等待 1~5 分钟解析生效，本地终端执行 `ping petrel-z.asia` 验证

## 三、部署过程中常见问题与解决方案
### 问题 1：上传中断占用服务器空间
- **现象**：SCP 上传中途中断，`node_modules`/`.git` 等冗余文件残留，占用大量空间
- **解决方案**：
  ```bash
  # 一键删除未传完的文件夹，释放空间
  rm -rf /root/blog
  ```
- **优化方案**：本地删除 `node_modules`/`.next`/`.git` 后再上传，或直接用 Git 拉取源码

### 问题 2：`nano: command not found`
- **现象**：服务器未安装 nano 编辑器，无法编辑配置文件
- **解决方案**：
  ```bash
  # 安装 nano 编辑器
  yum install -y nano
  # 或使用系统自带 vi 编辑器
  vi /etc/nginx/conf.d/blog.conf
  ```

### 问题 3：`ERR_CONNECTION_CLOSED` / 502 Bad Gateway
- **核心原因**：
  1.  腾讯云安全组未放行 80/3000 端口
  2.  Next.js 服务未正常监听 3000 端口
  3.  Nginx 反向代理配置错误
- **排查与解决**：
  ```bash
  # 1. 验证 Next.js 服务本地正常
  curl http://127.0.0.1:3000
  # 2. 验证端口监听状态
  netstat -tulpn | grep -E 'nginx|node'
  # 3. 重启 PM2 进程，恢复服务
  pm2 restart blog
  # 4. 检查安全组：腾讯云控制台放行 80/3000/443 端口
  ```

### 问题 4：域名无法解析（`ping: cannot resolve petrel-z.asia: Unknown host`）
- **核心原因**：域名未配置解析记录，或解析未生效
- **解决方案**：
  1.  按步骤 5 正确配置 A 记录
  2.  刷新本地 DNS 缓存（Mac 系统）：
      ```bash
      sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
      ```
  3.  用公共 DNS 验证解析：
      ```bash
      nslookup petrel-z.asia 223.5.5.5
      ```

### 问题 5：`firewall-cmd: command not found`
- **现象**：服务器系统未安装 firewalld 防火墙
- **解决方案**：无需安装，直接通过腾讯云安全组控制端口放行，避免本地防火墙干扰

## 四、关键注意事项
### 1. 代码部署优化
- **禁止上传冗余文件夹**：`node_modules`、`.next`、`.git` 无需上传，服务器直接安装依赖，避免跨平台兼容问题
- **优先使用 Git 拉取**：国内服务器推荐 Gitee 镜像，解决 GitHub 访问慢的问题

### 2. 进程与服务管理
- **PM2 核心作用**：守护 Next.js 进程，实现开机自启、崩溃自动重启，确保服务 24 小时在线
- **Nginx 配置规范**：必须配置 `proxy_set_header Host $host`，否则 Next.js 路由会异常

### 3. 网络与安全
- **安全组是第一道防线**：腾讯云服务器必须放行 80/3000/443 端口，否则外部无法访问
- **域名备案要求**：国内服务器绑定域名必须完成 ICP 备案，否则会被拦截访问
- **本地代理干扰**：访问时关闭浏览器代理/科学上网工具，避免网络异常

### 4. 故障排查流程
1.  本地验证：`curl http://127.0.0.1:3000` 确认服务正常
2.  端口验证：`netstat -tulpn` 确认 80/3000 端口正常监听
3.  网络验证：用服务器 IP 访问（`http://129.211.1.107:3000`），排除域名问题
4.  域名验证：`ping`/`nslookup` 确认解析生效
