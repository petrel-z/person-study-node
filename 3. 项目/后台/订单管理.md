# CRUDPageTemplate.tsx组件功能

功能概述
- 通用的“列表 + 查询 + 分页 + 新增/编辑弹窗 + 详情/历史记录”模板组件，面向所有 id 为数字的实体列表页面。
- 通过统一的 useCRUD 钩子封装数据获取、分页、增删改、详情、历史记录等业务流程。
- 提供可插拔的查询区、表格列、右上角新增按钮、行选择批量删除、行展开、以及自定义操作列渲染。
核心属性

- title : 页面与弹窗的标题前缀（如 新增{title} / 编辑{title}）。
- searchConfig : 查询表单的字段配置，交由 BaseSearch 渲染，提交触发 handleSearch 。
- columns : 表格列配置；配合 optionRender 可以扩展“操作”列。
- formConfig / addFormConfig : 编辑/新增表单配置；新增优先使用 addFormConfig ，否则用 formConfig 。
- apis : 五个可选 API 函数 fetchApi/createApi/updateApi/deleteApi/fetchHistoryApi ，传入 useCRUD 统一驱动数据流。
- 权限与交互控制： isAddOpen 、 disableCreate 、 disableBatchDelete 、 disableBatchUpdate 、 hideCreate 等。
- 导航： showNavigation 、 customNavActions 、 breadcrumbItems 控制面包屑与右上操作。
- 视觉与性能： scrollX 控制表格横向滚动阈值； onRow 透传行交互。
内部状态与数据流

- 通过 useCRUD 获取：
  - 列表相关： isLoading 、 tableData 、 page 、 pageSize 、 total 、 fetchTableData 、 handlePageChange 。
  - 查询/增删改： handleSearch 、 handleCreate 、 handleEdit 、 handleDelete 、 handleModalSubmit 。
  - 弹窗与数据： isCreateOpen 、 createTitle 、 createData 、 createFormRef 、 isCreateLoading 。
  - 详情/历史： isDetailOpen 、 detailData 、 handleDetail ； isHistoryOpen 、 historyData 、 handleHistory 。
- 首次渲染将 setFetch(true) ，随后 useEffect 监听 isFetch 触发 fetchTableData() 完成初次加载。
- 本地管理表格行选择 selectedRowKeys ，用于批量删除与按钮禁用状态。
渲染结构

- 顶层 BaseContent isPermission={true} 包裹，统一权限容器。
- 查询区： BaseCard 内渲染 BaseSearch ，提交后调用 handleSearch 。
- 列表区： BaseCard 内渲染 BaseTable ，支持：
  - 行选择与批量删除（ Popconfirm + BaseBtn ），禁用状态受权限控制。
  - 右侧新增按钮（受 isAddOpen 、 disableCreate 控制；点击触发 handleCreate ）。
  - 可选展开图标（ RightOutlined ），仅当记录存在 children 时展示。
  - 列配置可附加“操作”列：当传入 optionRender 时，模板注入四个动作方法。
- 分页： BasePagination 读取并回写 page/pageSize ，触发重新拉取数据。
- 弹窗：
  - 新增/编辑： BaseModal + BaseForm ，确认触发表单 submit ，提交走 handleModalSubmit 。
  - 详情： DetailModal （需 detailData 与 detailConfig ）。
  - 历史记录： HistoryModal （需 historyData ）。
交互与事件

- 批量删除：无选择时给出提示；调用 handleDelete(selectedRowKeys) 后清空选中。
- 操作列注入的动作：
  - handleEdit : 可先用 onEditOpen(record) 做数据预处理，再进入编辑流程。
  - handleDelete : 支持数组或单项 ID，删除后同步移除选中的行键。
  - handleHistory : 打开历史记录弹窗。
  - handleDetail : 打开详情弹窗。
- 新增：可先执行 onCreateClick() 自定义逻辑，再走统一的 handleCreate('新增' + title) 。
可扩展点

- 表单数据处理： handleFormValue 可在 useCRUD 里统一做入参格式化。
- 历史记录： formatHistoryData 用于后端数据到弹窗展示的映射。
- 操作列： optionRender(record, actions) 完全自定义渲染，使用模板注入的 actions 保持一致行为。
- 导航： TableNavigation 支持动态/自定义面包屑与右上按钮。
典型使用方式
- 在业务页面引入该模板组件，传入：
  - 查询配置 searchConfig 与表格列 columns 。
  - 表单配置 formConfig （可选 addFormConfig 用于新增）。
  - 标题 title 与必要的 apis 。
- 可选：根据权限控制传递 disableCreate/disableBatchDelete/disableBatchUpdate 等。
注意点
- T extends { id: number } ：数据行必须包含数字类型 id 字段，用于 rowKey 和删改操作标识。
- isDelete 当前仅用于 console.log ，未直接参与禁用逻辑，权限控制主要看 disableBatchDelete/disableBatchUpdate/disableCreate 。
- mockData 在此实现中未使用；数据流完全由 useCRUD 与 apis 驱动。
- 批量删除的 id 处理使用 Key[] ，确保传入与 rowKey 类型一致（默认 number ）。


# 字段

展示字段建议

- 基本标识
  - item_id （订单项ID，对应 OrderItem.ID ）
  - order_item_no （订单项号，对应 OrderItem.OrderItemNo ）
  - order_id （订单ID，对应 Order.ID ）
- 商品信息
  - product_name、 sku_description
  - quantity 、 price 、 total 、 payable_amount 、 refund_amount 、 gold_bean_amount
  - product_image_url （由 product_image_id 转换为 URL，便于后台直接展示）
- 状态与时间
  - item_status （数值状态）
  - item_status_text （中文状态文案，复用你项目中的状态映射）
  - expired_at 、 paid_at 、 verified_at 、 completed_at 、 cancelled_at 、 created_at
- 商家/店铺/用户
  - merchant_name
  - store_name
  - user_id、username 、 phone_masked （手机号不打码）
说明：

- 以上均能从你现有模型与联表取得： OrderItem 提供大部分商品与状态字段，订单号可从 Order 表，商家/店铺/用户信息来自各自表，图片与头像可通过 imageutils 从 ID 转 URL。
- 时间字段建议统一格式返回（如 YYYY-MM-DD HH:mm:ss ），你当前列表实现里已有 DATE_FORMAT 用法。
查询条件建议

- 基础分页与排序
  - page 、 page_size （默认 1 、 10 ，最大 100 ）
- 关键词搜索（综合维度）
  - keyword ：同时模糊匹配 order_item_no 、 product_name、store_name、user_phone ，并支持手机号模糊查询
- 状态与范围
  - item_status （0=全部；1=待支付；2=待使用；3=已完成；4=已取消；5=已过期；6=已退款；与现有映射保持一致）
  - start_time 、 end_time（时间范围）
- 维度筛选
  - province_name、 city_name、school_name

建议默认使用 created_at 的时间范围（例如最近一月）以提高检索效率
