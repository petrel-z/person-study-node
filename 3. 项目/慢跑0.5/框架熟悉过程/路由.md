### 路由工具函数（router index.ts）
#### 1. 路由解析函数 parseRoutes
- 作用：将 pages.json 中的 pages 和 subPackages 解析为扁平化的路由数组，并标记每个路由是否需要登录（needLogin）。

- 场景：初始化时生成全量路由表，后续用于权限校验、路由跳转判断等。

#### 2. 获取当前路由函数
- 作用：返回当前页面的完整路由路径（含/不含查询参数）。

- 场景：页面跳转前的判断、埋点、权限校验、返回上一页等。

#### 3. 去除查询字符串 removeQueryString
- 作用：去除路径中的查询参数，仅保留纯路径。

- 场景：路径比对、路由表查找等。

#### 4. 路径是否存在 isPathExists

- 作用：判断某个路径是否在已解析的路由表中存在。

- 场景：页面跳转前校验、404处理、权限拦截等。

#### 5. 是否为 tabBar 页面 isTabBarPath
- 作用：判断某个路径是否为 tabBar 页面（底部导航栏页面）。

- 场景：页面跳转时决定使用 switchTab 还是 navigateTo，tabBar 页面不能用 navigateTo 跳转。

### 权限拦截 plugins/permission.ts
#### 1. 白名单路由生成

- 作用：自动收集所有不需要登录的页面路径，形成白名单。

- 场景：白名单内的页面无需登录即可访问，如首页、公开页等。

#### 2. 权限校验函数 hasPerm

- 作用：

	- 判断目标路径是否存在（不存在则跳转 404）

	- 判断是否在白名单或已登录（有 token）

	- 无权限时自动跳转到登录页，并带上原目标路径（便于登录后重定向回原页面）

- 场景：所有页面跳转前的权限判断，防止未授权访问受限页面。

#### 3. 页面跳转 API 拦截

- 作用：

	- 拦截所有页面跳转 API（包括 tabBar 跳转），在跳转前执行权限校验

	- 校验不通过时阻止跳转，并自动重定向到登录页或 404

- 场景：全局注册后，所有页面跳转都自动带有权限拦截，无需在每个页面单独判断

# 路由相关完整流程
以下是本项目（uniapp-vue3-wx-template）中，所有与路由相关的完整流程，涵盖页面跳转、权限校验、权限拦截、未登录重定向等环节。流程涵盖了从路由声明、跳转、拦截、校验到最终页面渲染的全链路。

---

## 1. 路由声明与解析

- 所有页面在 pages.json 中声明（包括主包、分包、tabBar 配置等）。

- 启动时，src/router/index.ts 通过 parseRoutes 解析 pages.json，生成全量路由表 routes，并标记每个页面是否需要登录（needLogin 字段）。

- 关键页面路径（如首页、登录页、404页）以常量形式导出，便于全局引用。

---

## 2. 路由跳转发起

- 页面跳转通常通过 uni.navigateTo、uni.redirectTo、uni.reLaunch、uni.switchTab 等 API 发起。

- 跳转目标路径可能带有查询参数。

---

## 3. 路由拦截与权限校验

- 在 src/plugins/permission.ts 中，使用 uni.addInterceptor 全局拦截上述所有页面跳转 API。

- 每次跳转前，都会调用 hasPerm(path) 进行权限校验，流程如下：

1. 路径合法性校验

- 使用 isPathExists 判断目标路径是否在路由表中。

- 不存在则自动重定向到 404 页面。

1. 白名单校验

- 若目标路径在白名单（无需登录的页面），则直接放行。

1. 登录状态校验

- 若目标路径需要登录，且用户未登录（isLogin() 返回 false），则自动重定向到登录页，并携带原目标路径（redirect 参数）。

1. 有权限则放行

- 满足上述任一条件则允许跳转，否则拦截。

---

## 4. 页面渲染与生命周期

- 跳转成功后，页面正常渲染。

- 对于 tabBar 页面，由于小程序端 tabBar 点击不会触发 switchTab 拦截，需在 tabBar 页面 onShow 生命周期中再次做权限校验（如有需要）。

---

## 5. 登录后重定向

- 用户在登录页登录成功后，若 URL 中带有 redirect 参数，则自动跳转回原本想访问的受限页面，实现无缝体验。

---

## 6. 其他辅助功能

- currentRoute() 可获取当前页面完整路径，便于埋点、权限判断等。

- removeQueryString() 用于路径比对时去除查询参数，保证校验准确。

- isTabBarPath() 判断目标路径是否为 tabBar 页面，决定跳转方式（switchTab 或 navigateTo）。

---

## 总结流程图

1. 用户发起页面跳转（API/点击/编程式）

2. → 路由拦截器（permission.ts）拦截

3. → 校验路径是否存在

- 否 → 跳转 404

- 是 → 继续

1. → 校验是否白名单

- 是 → 放行

- 否 → 继续

1. → 校验是否已登录

- 是 → 放行

- 否 → 跳转登录页（带 redirect 参数）

1. → 跳转目标页面

2. → 若为 tabBar 页面，onShow 生命周期可再次校验

3. → 若登录后有 redirect，自动跳回原目标页

---

### 关键点

- 所有页面跳转都被全局拦截，权限校验无死角

- 未登录访问受限页自动重定向登录，登录后自动跳回

- 404、tabBar、白名单等特殊场景均有覆盖

- 路由表和权限标记自动从 pages.json 解析，维护简单

## 4. 权限校验主流程（src/plugins/permission.ts）

ts

Apply to index.ts

// src/plugins/permission.ts

import {

  ERROR404_PATH,

  isPathExists,

  LOGIN_PATH,

  removeQueryString,

  routes,

} from '@/router';

import { isLogin } from '@/utils/auth';

const whiteList = ['/'];

routes.forEach((item) => {

  if (item.needLogin !== true) {

    whiteList.push(item.path);

  }

});

export function hasPerm(path = '') {

  if (!isPathExists(path) && path !== '/') {

    uni.redirectTo({ url: ERROR404_PATH }); // 跳转404

    return false;

  }

  const hasPermission = whiteList.includes(removeQueryString(path)) || isLogin();

  if (!hasPermission) {

    uni.redirectTo({

      url: `${LOGIN_PATH}?redirect=${encodeURIComponent(path)}`, // 跳转登录页并带redirect

    });

  }

  return hasPermission;

}

## 5. 路由辅助方法（src/router/index.ts）

// src/router/index.ts

export function isPathExists(path = '') {

  const cleanPath = removeQueryString(path);

  return routes.some(item => item.path === cleanPath);

}

export function removeQueryString(path = '') {

  return path.split('?')[0];

}

export function isTabBarPath(path = '') {

  const cleanPath = removeQueryString(path);

  return (

    pagesJson.tabBar?.list?.some(

      item => `/${item.pagePath}` === cleanPath,

    ) === true

  );

}
