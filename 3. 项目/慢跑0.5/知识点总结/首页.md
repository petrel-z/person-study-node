防抖节流函数的类型注解问题
ts要求每一个变量都明确它的类型
1. 确保this上下文一致
	- 原函数 `fn` 可能依赖特定的 `this` 上下文（比如对象方法中的 `this`）。
	- 用 `ThisParameterType<T>` 可以**提取原函数 `fn` 定义的 `this` 类型**，并强制返回的节流函数也使用相同的 `this` 类型。
2. 确保参数类型与原函数一致
	- `Parameters<T>` 是 TypeScript 的工具类型，用于**提取原函数 `fn` 的参数类型**。
3. 如果没有类型限制，就会有any类型，失去类型检查的意义
```ts
/**

* 节流函数

* @param fu 要节流的函数

* @param delay 延迟时间（毫秒）

*/

export function throttle<T extends(...args: any[]) => any>(fn: T, delay: number): (this: ThisParameterType<T>, ...args: Parameters<T>) => void {

let last = 0;

return function (this: ThisParameterType<T>, ...args: Parameters<T>) {

const now = Date.now();

if (now - last >= delay) {

last = now;

fn.apply(this, args);

}

};

}
```
***类型定义：***
定义一个名为 `throttle` 的泛型函数，它接收两个参数：一个类型为 `T` 的函数 `fn`（`T` 是任意函数类型）和一个数字 `delay`。该函数返回一个新函数，这个新函数的 `this` 类型与原函数 `fn` 的 `this` 类型一致，参数类型也与原函数 `fn` 的参数类型完全相同，且没有返回值。


***节流函数最后一次不执行问题：***
当事件触发频率高于节流间隔（`delay`）时，若启用了尾调用（`trailing: true`），则在最后一次触发后的 `remaining` 时间（距离下一次允许执行的剩余时间）后，自动执行一次原函数，确保高频操作结束后，最后一次操作不会被忽略。
方法：定时器+时间戳
当timer=null时，说明还未触发最后一场执行，因此可以触发
就设置timer为新的定时器，定时器结束就可以重新执行fn函数，并且手动设置timer为null。


timer定时器在执行结束后，不会自动变成null，会是一个定时器ID，因此需要我们手动设置timer为null


***节流使用场景：***
输入搜索、窗口 resize、防重复点击

***防抖使用场景：***
滚动监听、鼠标跟踪、高频按钮点击
