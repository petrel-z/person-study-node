# 手机号一键登录
```vue
<button 
    open-type="getPhoneNumber" 
    @getphonenumber="handleGetPhoneNumber"
  >
    一键获取手机号
  </button>
```
需要在微信公众平台开通权限的小程序，前端点击button按钮会直接返回拒绝。

## 流程：
1. 前端点击button（获取用户手机号类型），获得手机号授权的code，传给后端
2. 后端通过code调用第三方[getPhoneNumber](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-info/phone-number/getPhoneNumber.html#%E5%8A%9F%E8%83%BD%E6%8F%8F%E8%BF%B0)接口，获得phone_info（用户手机号信息）
	1. 后端利用手机号查询用户是否注册
	2. 若已注册，返回token给前端
	3. 若未注册，根据手机号生成用户账户，并生成token返回给前端
3. 前端拿到token，进行登录

# 微信登录
## 流程：
1. wx.login   ==>  获得code，传给后端
2. 后端调用第三方[code2Session](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html#%E5%8A%9F%E8%83%BD%E6%8F%8F%E8%BF%B0)接口，获得session_key、unionid、openid等数据
	1. 根据openid / unionid 查询用户是否已注册
	2. 若已注册，直接关联现有用户账号
	3. 若未注册，创建新用户记录（以openid为唯一标识，可补充昵称、头像等信息）
3. 后端生成token，返回给前端
4. 前端拿到token，进行登录



# 混合流程：
1. 前端调用 wx.login   ==>  获得code，传给后端
2. 后端调用第三方[code2Session](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html#%E5%8A%9F%E8%83%BD%E6%8F%8F%E8%BF%B0)接口，获得session_key、unionid、openid等数据
3. 前端点击button（获取用户手机号类型），获得手机号授权的code，传给后端
4. 后端通过access_token、code、openid调用第三方[getPhoneNumber](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-info/phone-number/getPhoneNumber.html#%E5%8A%9F%E8%83%BD%E6%8F%8F%E8%BF%B0)接口，获得phone_info（用户手机号信息）
	1. 后端利用手机号查询用户是否注册
	2. 若已注册，返回token给前端
	3. 若未注册，根据手机号生成用户账户，并生成token返回给前端
5. 前端拿到token，进行登录


# 双token机制

登录成功后，拿到两个token
一个accsessToken，一个refreshToken

每次发送请求时，在请求头配置accessToken

请求发送后，得到响应，在响应拦截器里：
- 如果accessToken失效，code为401，需要重新刷新短token
- 用refreshToken来刷新短token
- 如果长token也失效，直接跳转到登录页面
- 如果没有失效，则短token刷新成功
- 重新保存长短token
- 重新发送请求，并执行请求队列中的请求


***为啥要重新发送请求，并执行请求队列中的请求？***
假如有三个请求A、B、C同时请求，且短token已经过期，
请求A首先到达响应拦截器，发现token已经过期，开始刷新短token
```javascript
// 请求 A 触发刷新
if (!isRefreshing) {
  isRefreshing = true;
  // 开始刷新 Token...
}
```
请求B、C随后到达，发现isRefreshing = true，它们不会触发新的刷新，而是被加入到请求队列中
```javascript
// 请求 B 和 C 被加入队列
return new Promise(resolve => {
  requestQueue.push(() => {
    resolve(http.request(config)); // 存储重试逻辑
  });
});
```
短token刷新成功后，请求A会重新发送自己http.request(config)
然后遍历请求队列，依次请求BC的重试函数

这样解决了重复刷新token 以及 请求雪崩的问题
