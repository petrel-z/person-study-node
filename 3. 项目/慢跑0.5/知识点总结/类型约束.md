# 为什么需要类型约束
ts在编译时
当使用obj[key]时，ts需要确保
1. 该属性确实存在在对象上
2. 返回值的类型是已知的
ts无法确定属性是否存在，如果该索引对应的对象中的元素不存在，该返回什么类型

js运行：
```js
// JavaScript 允许任意属性访问
const obj = { name: '王五' };
console.log(obj['name']); // '王五'
console.log(obj['unknown']); // undefined
```
ts编译时：
```ts
// TypeScript 需要在编译时确定类型安全
interface Obj {
name: string;
}
const obj: Obj = { name: '王五' };
// TypeScript 问：obj['unknown'] 应该返回什么类型？
```

# 类型约束的方式
## 索引签名
### 作用：
```ts
interface FlexibleObj {
name: string;
[key: string]: any; // "我允许任意字符串键，返回 any 类型"
}
```
这相当于对 TypeScript 说：
- "这个对象可能有我没有明确定义的属性"
- "当通过字符串键访问时，返回指定的类型"

### 定义方式
在接口中定义：
```ts
export interface MerchantEnterReq {

phone: string; // 手机号
...
// 索引签名
[key: string]: any; 
// 更严格的类型约束
[key: string]: string | number | string[] | null; 

}
```

交叉类型：
```ts
export interface MerchantEnterReq {
identity: number;
phone: string;
...
}

export type MerchantEnterReqWithIndex = MerchantEnterReq & {
[key: string]: any;
};
```

### 使用方式：
1. ***动态属性访问***
```ts
const merchantData: MerchantEnterReq = {

identity: 1,

phone: '13800138000',

// ... 其他属性

};

// 安全地使用字符串索引访问
const phoneValue = merchantData['phone'];
const dynamicKey = 'storeName';
const storeNameValue = merchantData[dynamicKey]; 
```
2. ***循环里使用***
```ts
const keys = ['phone', 'site', 'merchant_name'];
keys.forEach(key => {
	const value = merchantData[key]; 
	console.log(`${key}: ${value}`);
});
```
3. ***表单处理中使用***
```ts
// 在 Vue 组件中
const updateFormValue = (fieldName: string, newValue: string) => {
	merchantForm[fieldName] = newValue;
};
// 批量更新表单
const updateMultipleFields = (updates: Record<string, any>) => {
	Object.keys(updates).forEach(key => {
		merchantForm[key] = updates[key];
	});
};
```

如果不定义标签索引，在ts中使用索引来访问对象就会报错



## Record类型
Record<K, T> 是 TypeScript 内置的工具类型，用于创建一个对象类型，其中所有属性的键类型为 K ，值类型为 T 。

### 用法：
```ts
type User = Record<string, any> & {
name: string;
age: number;
};
const obj: User = {
	name: 'xiaohong',
	age: 0,
}
```
键可以是联合类型
```ts
type Status = 'pending' | 'success' | 'error';
type StatusConfig = Record<Status, string>;
```
值可以是复杂值类型
```ts
type UserInfo = {
name: string;
age: number;
};

type UsersDatabase = Record<string, UserInfo>;
```

### 应用：
1. 创建表单类型
```ts
// 定义表单字段名
type FormFields = 'phone' | 'site' | 'storeName' | 'merchant_name';

// 创建表单类型
type FormData = Record<FormFields, string | null>;

const formData: FormData = {
phone: '13800138000',
site: '北京市朝阳区',
storeName: null,
merchant_name: '商家名称'
};
```
```ts
export type MerchantEnterReq = Record<string, string | number | string[] | null> & {
identity: number;
storeName: string | null;
merchant_name: string;
};
```

### 交叉类型
#### 应用
&表示交叉类型
这里的 & 将两个类型合并：
 左边： Record<string, string | number | string[] | null>
- 允许任意字符串键
- 值类型限制为 string | number | string[] | null
- 提供动态属性访问能力 
右边： { identity: number; phone: string; ... }
- 明确定义的具体属性
- 每个属性都有精确的类型

合并结果：
```ts
// 最终类型具备以下特性：
type MerchantEnterReq = {
// 明确定义的属性（来自右边）
identity: number;
storeName: string | null;
merchant_name: string;

// 同时支持任意字符串键（来自左边的 Record）
[key: string]: string | number | string[] | null;
};
```
好处：
1. 兼顾类型安全和灵活性
2. 解决索引访问问题

#### 其他应用：
混入：
```ts
type Timestamped = {
createdAt: Date;
updatedAt: Date;
};

type User = {
name: string;
email: string;
};

type UserWithTimestamp = User & Timestamped;
```
扩展现有类型：
```ts
type BaseConfig = {
apiUrl: string;
timeout: number;
}; 

type DevConfig = BaseConfig & {
debug: boolean;
mockData: boolean;
};
```

#### 交叉类型和联合类型的区别：
```ts
// 交叉类型 &：必须同时满足所有类型
type A = { name: string } & { age: number };
// 对象必须同时有 name 和 age 属性 

// 联合类型 |：满足其中一个类型即可
type B = { name: string } | { age: number };
// 对象可以只有 name，或只有 age，或两者都有
```

## 类型断言

```ts
const value = (user as any)[key];
```

## keyof操作符

```ts
function getValue<T, K extends keyof T>(obj: T, key: K): T[K] {
	return obj[key];
}
```


# 类型约束的作用
- 防止拼写错误 ： user.naem 会被捕获
- 类型安全 ：确保返回值类型正确
- IDE 支持 ：更好的自动补全和错误提示
- 动态属性访问 ：表单处理、API 数据
- 运行时确定的键 ：循环遍历、配置对象

- 1.保证类型安全 ：确保您知道在做什么
- 2.提供更好的开发体验 ：IDE 提示、错误检查
- 3.防止运行时错误 ：在编译时发现潜在问题
