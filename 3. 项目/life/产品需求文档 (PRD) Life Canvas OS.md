
## 产品概述

Life Canvas OS 是一个前卫的个人成长全维度操作系统。该项目将 React 19、Tailwind CSS 4.0 和 Google Gemini AI 引擎深度融合，构建了一个高度模块化、可视化的生命管理生态。其设计目标是打破传统笔记和任务软件的碎片化，通过 8 个核心维度的“系统化”抽象，为用户提供一个集状态感知、深度产出、资产管理与 AI 决策于一体的人生数字化座舱。

## 产品定位

* **目标用户：** 追求极客精神的高绩效人士、数字游民、以及希望对生活进行“系统级建模”与“精细化治理”的自我成长者。

* **核心痛点：** 解决用户在多重角色切换中的认知载荷过重、生活状态失衡不可见、以及碎片化工具（如单独的记账、健身、笔记软件）导致的数据孤岛问题。

* **市场价值：** 提供一种“低功耗录入、高维度可视化、AI 辅助决策”的生命治理模型，将抽象的人生平衡转化为可量化的系统工程。

  

## 核心功能

* **全维度平衡画布 (Equilibrium Map):** 基于 Recharts 的 8 维度雷达图，直观反馈燃料、硬件、输入、产出、恢复、资产、连接与环境的实时稳态。

* **AI 神经洞察 (Neural Insights):** 集成 Gemini 3 Flash，自动分析系统数据并生成“庆祝、预警、行动”三类深度分析报告。

* **深度工作站 (Deep Work Station):** 融合 OKR 目标管理与番茄钟协议，支持心流状态的量化记录。

* **基准线模型 (Baseline Modeling):** 创新性采用“基准录入”逻辑，仅记录偏离状态，极大降低日常维护的认知损耗。

* **跨维审计日志 (Temporal Audit):** 全系统统一的时间轴审计追踪，记录每一次生命状态的迭代。

* **内核配置 (Kernel Config):** 基于用户价值观 (Values) 和人格特征 (MBTI) 的个性化系统参数设定。

  

## 需求

  

### 需求 1: 全局画布可视化与交互

**用户故事:** 作为用户，我想看到一个 8 维度的雷达图，以便我能一眼识别当前生活的短板与平衡状态。

  

**验收标准**

* 系统应在主界面显示包含 FUEL、PHYSICAL、INTELLECTUAL、OUTPUT、RECOVERY、ASSET、CONNECTION、ENVIRONMENT 8 个维度的雷达图。

* 当子系统分数更新时，雷达图应平滑过渡到新形态。

* 雷达图上的标签应支持点击，点击后跳转至对应的子系统详情页。

* 系统应通过颜色区分不同维度的状态，并提供全局平衡得分的百分比显示。

  

### 需求 2: 子系统钻取与双视图模式

**用户故事:** 作为用户，我想点击进入某个子系统（如资产系统），在“实时同步”与“基准架构”间切换，以便管理实时动态或修改底层配置。

  

**验收标准**

* 用户点击子系统卡片时，应以平滑动画滑入详情面板。

* 详情面板应提供“实时同步”视图，用于记录日常行为日志。

* 详情面板应提供“基准架构”视图，用于定义该系统的常态参数（如每日饮食基准、每周运动计划）。

* 在基准架构中修改参数并点击“同步”后，系统应持久化数据并显示反馈动画。

  

### 需求 3: AI 神经洞察引擎

**用户故事:** 作为用户，我想让 AI 扫描我的全维度数据，给我提供专业、客观的人生改进建议。

  

**验收标准**

* 点击“启动 AI 洞察”按钮时，系统应触发 Gemini API 调用，并显示加载状态。

* AI 报告必须包含：针对最高分的“庆祝”卡片、针对最低分的“预警”卡片、以及针对全局平衡的“行动建议”卡片。

* 报告内容应以 Markdown 或结构化列表形式展示，易于阅读。

* 如果 API 调用失败，系统应展示优雅的错误处理并提供降级的本地缓存建议。

  

### 需求 4: 深度工作与 OKR 管理

**用户故事:** 作为用户，我想在一个界面内启动番茄钟并跟踪我的 OKR 目标，以便最大化我的产出。

  

**验收标准**

* 工作系统应内置番茄钟（25/5 节奏），支持启动、暂停、重置功能。

* 当番茄钟完成一个周期时，系统应自动弹窗并提示用户记录一条“专注流”日志。

* OKR 管理器应支持创建 Object 和 Key Results，并以进度条展示达成率。

* 当 OKR 的所有 Key Result 完成时，系统应自动更新 OUTPUT 维度得分。

  

### 需求 5: 时间轴审计追踪 (Timeline Audit)

**用户故事:** 作为用户，我想查看所有系统的历史操作记录，以便复盘我的成长轨迹。

  

**验收标准**

* 审计日志页面应按时间倒序排列所有系统的 Log 条目。

* 每个日志条目应显示所属系统、时间戳、操作类别（如“火花”、“系统同步”）及具体值。

* 日志流应具备垂直时间轴引导线，并支持按系统类型进行快速过滤。

* 当用户在子系统内添加一条日志时，该日志应实时同步至全局审计流。

  

### 需求 6: 内核配置与生命进度监控

**用户故事:** 作为用户，我想设定我的出生日期、MBTI 和核心价值观，并查看我当前的“生命已用时长”。

  

**验收标准**

* 配置页面应允许用户输入姓名、生日、MBTI 和 3-5 条核心价值观。

* 系统应根据生日和预设寿命（如 85 岁）计算出“系统已分配时间资源”百分比，并以进度条展示。

* 价值观应作为系统的“指令集”存储，并在 AI 洞察中作为上下文参考。

* 支持“注销连接”功能，用于清除本地缓存并返回认证界面。

  

### 需求 7: 认证与数据持久化隔离

**用户故事:** 作为用户，我想确保我的生命数据只保存在我的设备上，或者与我的身份信息绑定，以保护隐私。

  

**验收标准**

* 当用户首次访问时，应显示“神经链接建立”界面（模拟登录/注册）。

* 系统应验证邮箱格式及必填字段，并在本地 LocalStorage 中加密存储用户信息。

* 未认证用户尝试访问系统时，应重定向至认证页面。

* 系统应在主页面显示“当前操作员”信息，确保用户明确其数据归属
