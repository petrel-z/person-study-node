
1. 闭包的形成的条件
	1. 存在**内部函数**（定义在另一个函数内部）。
	2. 内部函数**在其定义的作用域之外被执行**，且**引用了作用域内的变量**。
2. 闭包的生命周期

看这个🌰：

```js
function outer() {
	const a = 1;
	return { a: a++, b: 2 };
}
const obj = outer();
console.log(obj);
console.log(obj);
console.log(obj);
```
![[Pasted image 20250718105920.png]]
为啥它无法形成闭包，即使返回的对象引用了函数内部的变量？
因为函数在返回对象时，只是将值复制给对象中的属性，也就是说对象中的属性只是对值的静态调用。并没有其他地方在引用outer函数内部的变量，所以outer内部的a变量在函数执行完被销毁了。
outer函数执行结束后，变量a的值复制到返回的对象中，返回的对象赋值给了obj，outer的作用域被销毁，外部的obj与outer作用域没有任何关系了。无论我们打印多少次obj结果永远是{a: 1, b: 2}!!!

```js
function outer1() {
    let a = 1;
    return function(){
        console.log(a++);
    };
}
let fn = outer1();
fn();
fn();
fn();
```
再看这个🌰：
被返回的函数，原本的作用域只有在outer1函数内部才能执行，它能访问的变量的作用域不仅有outer1函数的变量，还能访问，outer1外部，也就是全局作用域的变量，那如果内部函数只是在outer1函数里执行，而没有返回，内部函数在执行完就被销毁，outer1也被销毁，但是如果这个内部函数被返回，这个内部函数在outer1函数外部被执行，这个内部函数能访问变量的作用域没有被销毁，这就是闭包，它仍能访问outer1里面的变量，那outer1是不是也没有被销毁


核心：
**一个函数在其词法作用域之外执行时，依然能访问和操作该作用域内的变量**。
**内部函数在定义的作用域之外执行时，仍能访问该作用域的变量**

[[作用域与词法作用域]]


闭包形成的本质是，内层函数引用了外层函数的变量，导致外层函数的变量不会被垃圾回收机制回收。
内层函数在执行时，形成了对对外层函数作用域的引用，因此内层函数一直能通过作用域链找到外层函数的作用域，也就能找到外层函数的变量了，而外层函数的变量没有被回收，因此出现了闭包现象。
