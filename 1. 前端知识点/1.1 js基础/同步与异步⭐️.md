### js为什么要设计为单线程？
- 因为js是用于网页交互而产生的脚本语言，通常会伴有操作dom的行为。如果js设计为多线程，一个线程改变了dom，另一个线程删除了这个dom，那浏览器就不知道听哪个线程了，这就是经典的线程同步问题。
- 因此为了避免线程同步的问题，干脆直接将js设计为单线程的，让js一次只做一件事。

### js虽然是单线程，但它有两种设计模式
**同步模式：** 按照代码出现先后顺序执行。
	同步会遇到一个问题：如果遇到一个耗费时间非常多的函数，在执行过程中，js会执行完该耗时的函数才会执行下一行代码，这就会导致耗时的代码阻塞了后面的代码执行。
	因此，异步模式诞生了
**异步模式：** 将耗时的代码进行归类，一部分放在微任务队列中执行，一部分放在宏任务队列中执行，这些任务队列中的任务不会阻塞执行栈中的任务的执行。

Promise就是异步模式的体现
#### promise的基本概念
promise有三种状态：padding进行中、resolved已成功、rejected已失败
当回调函数执行完毕后，如果没有错误抛出，promise的状态变成已成功，且将返回的结果当成成功状态的值，如果没有返回结果，则成功状态的值为undifined
若有错误抛出，promise的状态变成已失败
then中传入的两个回调函数分别是处理成功状态的回调函数（onFulfilled）和处理失败状态的回调函数（onRejected），如果promise执行器函数中调用了resolve函数，就让promise的状态变为成功，且会执行then函数中处理成功状态的回调函数onFulfilled
```js
Promise.resolve(1)
  .then(res => res + 1) // 回调返回 2（非 Promise）
  .then(res => console.log(res)); // 新 Promise 已完成，接收 2

Promise.resolve(1)
  .then(res => new Promise(resolve => resolve(res + 1))) 
  .then(res => console.log(res)); // 最后一个 then

Promise.resolve(1)
  .then(res => new Promise(resolve => resolve(res + 1)))
  .then(res => {
    console.log(res); // 打印 2
    return res; // 显式返回 res（2），作为新 Promise 的成功值
  })
  .then(finalRes => console.log(finalRes)); // 这里会打印 2
```
执行了onFulfilled后，js引擎会根据这个回调函数的执行结果返回新的promise对象。
有如下规则：
该then不管onFulfilled回调函数的执行结果如何，都会返回新的promise，从而实现了then的链式调用
1. 如果onFulfilled返回的是非promise对象，则创建的新的promise对象状态变成已成功，值为onFulfilled返回的值
```js
Promise.resolve(1)
  .then(res => {
    console.log("第一个回调执行", res); // 输出：第一个回调执行 1
    return res + 1; // 返回普通值 2
  })
  .then(res => {
    console.log("第二个回调执行", res); // 输出：第二个回调执行 2
  });
// 第一个 then 返回的新 Promise 状态为成功，结果为 2
```
2. 如果onFulfilled返回的是promise对象，则新的promise的状态变成等待，等待返回的promise对象的结果改变，然后继承它的结果。
	1. 若返回的 Promise 成功，新 Promise 也变为成功，结果为其成功值；
	2. 若返回的 Promise 失败，新 Promise 也变为失败，结果为其失败原因。
```js
Promise.resolve(1)
  .then(res => {
    // 返回一个新 Promise
    return new Promise(resolve => {
      setTimeout(() => resolve(res + 1), 1000);
    });
  })
  .then(res => {
    console.log("第二个回调执行", res); // 1秒后输出：第二个回调执行 2
  });
// 第一个 then 返回的新 Promise 会等待内部返回的 Promise 完成，最终变为成功状态

```
3. 如果onFulfilled抛出异常，新的promise会变成失败状态，并传递给下一个then的失败回调
```js
Promise.resolve(1)
  .then(res => {
    throw new Error("出错了"); // 抛出异常
  })
  .catch(err => {
    console.log("捕获错误", err.message); // 输出：捕获错误 出错了
  });
// 第一个 then 返回的新 Promise 状态为失败，原因是 Error 对象
```

resolve函数和reject函数是js引擎内部提供的
在创建promise对象时，需要传入一个**执行器函数**，resolve和reject作为参数传入这个执行器函数
执行器函数会根据异步结果调用这两个参数
```js
let promise = new Promise((resolve, reject) => {
  // 函数体
});
```
