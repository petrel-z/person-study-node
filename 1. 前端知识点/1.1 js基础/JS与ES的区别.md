
js是一种运行在浏览器的编程语言
es是js的规范

# 解释和编译的区别
- **解释执行**：代码 → **解释器** → 逐行解析为**抽象语法树（AST）** → 直接执行对应操作；不生成中间代码，适合快速启动（如脚本语言）。
- **编译执行**：代码 → **编译器** → 生成**机器码（如 C）或字节码（如 Java）** → 执行；需提前编译，性能更高但启动慢。

编程语言类型：
- **解释型**：JavaScript、Python、Ruby、PHP
- **编译型**：C、C++、Go、Rust
- **既有编译又有解释**：Java（先编译为字节码，再解释 / 即时编译执行）、C#（IL 中间语言 + JIT 编译）、js V8引擎

# es的作用
1. **统一标准**：定义 JavaScript 语法和核心 API，消除浏览器差异。
2. **推动进化**：通过 TC39 委员会管理提案，每年发布新特性（如 ES6 的箭头函数、Promise）。
3. **兼容保障**：强制浏览器厂商遵循规范，提升代码跨平台一致性。
4. **语言健壮性**：修复设计缺陷（如严格模式），引入现代语法（如模块化、async/await）。
5. **生态基石**：为 TypeScript、Babel 等工具链提供标准化基础。


# JavaScript 执行路径核心逻辑
1. **执行策略取决于代码特性**
    
    - **非热点代码**（如事件回调）：仅通过解释器（Ignition）生成字节码直接执行，无需编译。
    - **热点代码**（如循环 / 高频函数）：先解释执行并监控，达到阈值后 JIT 编译器（TurboFan）将字节码编译为机器码，性能提升 10-100 倍。
2. **动态优化机制**
    
    - **触发编译条件**：高频执行且类型稳定（如变量类型不变）。
    - **类型变化时**：丢弃机器码，回退到字节码解释执行，待类型稳定后可能再次编译。
3. **性能权衡**
    
    |代码类型|执行流程|编译触发|性能|
    |---|---|---|---|
    |非热点代码|解释器 → 字节码执行|否|中|
    |稳定热点代码|解释器 → JIT 编译 → 机器码|是|高|
    |动态变化热点代码|解释 → 编译 → 回退解释|多次|波动|
    

**核心结论**：引擎通过**动态切换执行模式**，在启动速度（解释）与运行效率（编译）间取得平衡。




1. **解释执行**：首次执行时，解释器（Ignition）快速生成字节码并执行。
2. **编译执行**：热点代码通过 JIT 编译器（TurboFan）编译为机器码，提升性能。
3. **动态优化**：若类型变化，丢弃机器码回退到解释执行。

**关键区别**：
- JS 的编译是**运行时动态编译**（JIT），而非提前编译（AOT）。
- 早期 JS 是纯解释型，现代引擎通过 JIT 融合了编译特性。
