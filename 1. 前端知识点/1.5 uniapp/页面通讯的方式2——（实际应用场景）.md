### 1. 购物车数量跨页面实时更新  
- **场景描述**：商品详情页点击“加入购物车”后，底部tabBar的购物车图标数字需即时更新；购物车页修改数量后，结算页也需同步变化。  
- **首选方式**：Pinia 全局状态管理  
  - 原理：购物车数据（如 `cartStore.goodsList`、`cartStore.totalCount`）存在全局Store中，任何页面修改后，依赖该数据的UI自动响应。  
  - 实战示例：  
    ```typescript
    // 商品详情页加入购物车
    const cartStore = useCartStore();
    const addToCart = (goods) => {
      cartStore.addGoods(goods); // 调用Store方法更新数据
    };

    // 购物车tabBar组件中显示数量
    const cartStore = useCartStore();
    // 直接使用响应式数据，自动更新
    const totalCount = computed(() => cartStore.totalCount);
    ```  
- **备选方式**：若仅需通知更新（无需共享具体数据），可用事件总线（如 `bus.emit('cartUpdate')`），各页面监听后重新拉取接口。  


### 2. 多步骤表单跨页传递数据（如注册/下单流程）  
- **场景描述**：用户注册分3步（基本信息→验证手机→设置密码），每步填写的数据需传递到下一步；或下单流程（选择商品→填写地址→支付），各步骤数据需汇总。  
- **首选方式**：Pinia 或 Storage（临时存储）  
  - 用Pinia：适合步骤间需频繁读写、数据较复杂的场景（如表单验证状态）。  
    ```typescript
    // 步骤1页面存储数据
    const formStore = useFormStore();
    formStore.setStepData(1, { username: 'test', phone: '13800000000' });

    // 步骤2页面读取并补充数据
    const formStore = useFormStore();
    const step1Data = formStore.getStepData(1);
    formStore.setStepData(2, { ...step1Data, code: '1234' });
    ```  
  - 用Storage：适合步骤间跳转可能跨页面栈（如 `redirectTo`）、需临时持久化的场景（防止用户中途退出后重新进入仍可恢复）。  
    ```typescript
    // 步骤1存储
    uni.setStorageSync('registerForm', { step: 1, data: { username: 'test' } });
    // 步骤2读取
    const form = uni.getStorageSync('registerForm') || { step: 1, data: {} };
    ```  
- **避免方式**：路由参数（数据量大易超限）、事件通道（步骤跳转可能用 `redirectTo` 导致通道失效）。  


### 3. 列表页进入编辑页，返回后刷新列表  
- **场景描述**：从“订单列表页”进入“订单编辑页”，修改订单状态后返回列表页，列表需自动刷新最新数据。  
- **首选方式**：事件通道 + onShow 结合  
  - 编辑页回传更新信号，列表页接收后标记“需刷新”，在 `onShow` 中执行刷新（确保页面重新显示时触发）。  
  - 实战示例：  
    ```typescript
    // 列表页打开编辑页
    uni.navigateTo({
      url: '/pages/order-edit/index?orderId=123',
      events: {
        orderUpdated: () => {
          // 标记需要刷新
          needRefresh.value = true;
        }
      }
    });

    // 列表页onShow中刷新
    onShow(() => {
      if (needRefresh.value) {
        fetchOrderList(); // 重新拉取列表
        needRefresh.value = false;
      }
    });

    // 编辑页保存后通知
    const eventChannel = uni.getOpenerEventChannel();
    const saveOrder = () => {
      // 调用接口保存...
      eventChannel.emit('orderUpdated');
      uni.navigateBack();
    };
    ```  
- **备选方式**：用Store存储“最后编辑的订单ID”，列表页 `onShow` 时检查是否有更新并刷新。  


### 4. 全局通知（如系统公告、消息提醒）  
- **场景描述**：小程序任何页面可能收到新消息（如客服消息、系统通知），需在页面顶部显示提示条，点击可进入消息中心。  
- **首选方式**：Pinia + 响应式订阅  
  - Store中存储消息状态，各页面通过 `watch` 监听变化，触发UI更新。  
  - 实战示例：  
    ```typescript
    // 消息Store
    export const useMessageStore = defineStore('message', {
      state: () => ({ newMessage: null as { id: string; content: string } | null }),
      actions: {
        setNewMessage(msg) {
          this.newMessage = msg;
        }
      }
    });

    // 全局消息提示组件（在App.vue中引入）
    const messageStore = useMessageStore();
    watch(
      () => messageStore.newMessage,
      (newMsg) => {
        if (newMsg) {
          showToast(newMsg.content); // 显示提示
        }
      }
    );

    // 消息推送时更新Store（如WebSocket回调中）
    const onMessageReceived = (msg) => {
      const messageStore = useMessageStore();
      messageStore.setNewMessage(msg);
    };
    ```  
- **避免方式**：事件总线（全局事件过多易冲突，且难以统一管理）。  


### 5. 临时缓存未提交的表单数据（防止页面关闭丢失）  
- **场景描述**：用户在“发布商品页”填写大量内容（如标题、详情、图片），可能中途切换到其他页面（如选择图片、查看帮助），返回后需恢复之前填写的内容。  
- **首选方式**：Storage + onUnload 自动保存  
  - 页面卸载时（`onUnload`）将表单数据存入Storage，页面加载时（`onLoad`）读取并恢复。  
  - 实战示例：  
    ```typescript
    // 发布商品页
    const productForm = reactive({ title: '', content: '', images: [] });

    // 页面加载时恢复
    onLoad(() => {
      const cached = uni.getStorageSync('draftProduct');
      if (cached) {
        Object.assign(productForm, cached);
      }
    });

    // 页面卸载时缓存（包括跳转到其他页面或退出）
    onUnload(() => {
      uni.setStorageSync('draftProduct', productForm);
    });

    // 提交成功后清除缓存
    const submit = () => {
      // 调用接口提交...
      uni.removeStorageSync('draftProduct'); // 提交后删除草稿
    };
    ```  
- **注意**：敏感信息（如价格、库存）需加密存储，或在退出小程序时自动清理（`onHide` 中判断是否为退出状态）。  


### 6. 权限验证状态跨页面共享（如登录/会员状态）  
- **场景描述**：多个页面（个人中心、支付页、专属优惠页）需判断用户是否登录/是否为会员，未登录时跳转登录页，登录后返回原页面并刷新。  
- **首选方式**：Pinia + 路由守卫  
  - Store存储登录状态（`userStore.isLogin`），路由跳转前通过守卫检查权限，登录后更新状态并触发原页面刷新。  
  - 实战示例：  
    ```typescript
    // 用户Store
    export const useUserStore = defineStore('user', {
      state: () => ({ isLogin: false, userInfo: null }),
      actions: {
        login(userData) {
          this.isLogin = true;
          this.userInfo = userData;
        }
      }
    });

    // 路由守卫（在main.ts中配置）
    router.beforeEach((to, from, next) => {
      const userStore = useUserStore();
      if (to.meta.needLogin && !userStore.isLogin) {
        // 记录需要返回的页面，登录后跳转回来
        uni.setStorageSync('redirectAfterLogin', to.path);
        next('/pages/login/index');
      } else {
        next();
      }
    });

    // 登录页登录成功后
    const loginSuccess = () => {
      const userStore = useUserStore();
      userStore.login(res.data);
      const redirectPath = uni.getStorageSync('redirectAfterLogin') || '/pages/index/index';
      uni.navigateTo({ url: redirectPath });
    };
    ```  


### 总结：场景与方式的核心匹配原则  
- **单次跳转传简单数据** → 路由参数  
- **父子页面双向交互** → 事件通道  
- **多页面共享/实时同步** → Pinia  
- **持久化/跨流程数据** → Storage  
- **全局通知/状态变更** → Pinia + 响应式订阅  
- **临时缓存/防丢失数据** → Storage + 生命周期钩子  

根据业务复杂度和数据特性选择，优先保证低耦合和可维护性。
