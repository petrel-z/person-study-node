## 学习输出

### 1. 什么是 Structured Output？

它翻译为中文的意思是：结构化输出

我们要求模型按照我们想要的json格式进行输出

比如约束大模型，必须用json格式来输出

大模型可以将返回的数据以json格式输出，但是具体的字段名称，有哪些字段，大模型的输出是不确定的

因此结构化输出的主要目的，就是告诉大模型，要输出的json格式的字段多少、字段类型、字段名称、字段是否必须等

这个结构体就是**Schema**

例如，我们想让大模型输出的结构为：
```json
{
  "title": "文章标题",
  "summary": "文章概要",
  "url": "文章链接"
}
```

对应的Schema就需要告诉llm：
- 必须输出一个对象
- 对象里有title、summary、url字段
- 三个字段都是字符串
- 每个字段都是必须的，不能多也不能少

那这个Schema大概就是：
```json
{
  "type": "object",
  "properties": {
    "title": {
      "type": "string",
      "description": "文章标题"
    },
    "summary": {
      "type": "string",
      "description": "文章概要"
    },
    "url": {
      "type": "string",
      "description": "文章链接"
    }
  },
  "required": ["title", "summary", "url"],
  "additionalProperties": false // 表示不允许schema之外的额外字段
}
```

通过这个Schema来约束大模型输出的格式
这就相当于给了大模型一张表单，让它按要求来填写这个表单即可


### 2. 它和“让模型输出 JSON”有什么区别？

如果只告诉大模型“按照json输出”

大模型可以按照json的格式输出，但是具体的字段名称、有多少个字段、字段类型是啥... 它都不清楚，并且每次大模型输出的json内容也是不稳定的，那么大模型给的json数据就不能被程序很好的去解析。
当我们给模型提供了Schema后，大模型就严格按照我们提供的格式去输出，那么大模型输出就是可靠稳定的，这样我们后续程序处理时就比较方便了


### 3. 它解决了什么问题？

主要解决大模型输出不可控的问题：
1. 字段名称不稳定
2. 字段类型不稳定
3. 缺失字段，或者多出额外字段
4. json前后混入自然语言，导致json解析失败


### 4. 它和 Tool Calling 的关系是什么？

- 它们二者之前其实有相同点，本质都是让大模型生成稳定的结构化输出
- 它们的不同点其实在于：llm输出的结构化数据的用处不同
	- tool calling 中的结构化输出数据，主要用于给程序执行的动作，是让程序能准确的调用某个工具
	- 而Structured Output的结构化输出，是最终结果的结构化输出，是让最终结果按照固定格式返回
	- 返回的结果可以进行后续操作：
		- 展示到页面
		- 写入数据库
